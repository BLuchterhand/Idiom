# Start Here

This kit helps a team choose one AI workflow, set the authority boundary, and
run a pilot that can say no.

## Pick The Right First Workflow

Choose a workflow where:

- one decision or work state can be named;
- the highest-risk claims have identifiable sources;
- the first useful AI output can remain in draft assistance or reviewed proposal mode;
- a reviewer can inspect the packet without reconstructing the work;
- missing evidence can block, return, or escalate the packet;
- the team can run a weekly review of accepted and rejected work.

Do not start with a workflow where:

- no one owns the current source;
- reviewers have no funded time;
- the first launch requires direct customer, money, record, filing, or production effects;
- rejection would be politically impossible;
- the team cannot observe what the AI output changed.

## Choose The Authority Mode

| If the workflow has... | Start in this mode | Required artifact |
| --- | --- | --- |
| Unclear decision, missing owner, or disputed source | Discovery only | Workshop notes and source-owner backlog |
| Clear draft value, but incomplete acceptance path | Draft assistance | Decision acceptance contract |
| Clear sources, reviewer, and blocked state | Reviewed proposal | Claim matrix and reviewer packet |
| Review, permission, rollback, logging, and owner after acceptance | Bounded action | Effect-boundary spec and control-validation loop |

Use one ladder throughout the pilot: discovery only, draft assistance, reviewed
proposal, bounded action. Personal-assistant use is the individual-use form of
draft assistance.

## First 30 Minutes

1. Name the decision.
2. Name the first prohibited effect.
3. Name the highest-risk claim.
4. Name the source owner for that claim.
5. Name who can reject the packet.

If the team cannot answer those five questions, keep the workflow in discovery
or draft assistance.

## First 90 Minutes

Run `01-90-minute-workshop-guide.md`. The workshop should produce:

- one decision acceptance contract;
- one claim-to-evidence matrix;
- one reviewer packet outline;
- one capacity estimate;
- one stop condition;
- one Week 0 owner list.

## First Three Weeks

Use `02-pilot-operating-guide.md`.

The pilot should not scale until accepted verified output, review capacity,
stale-source behavior, bypass pressure, and escaped unsupported decisions are
visible.
