# AI Adoption Book Workspace

This directory contains the current planning, research, and drafting guidance
for **Trust the Process, Not the Prompt: How to Turn AI Output Into Trusted
Work**.

## Canonical Vision

AI adoption fails when fluent probabilistic output is allowed to become
operational authority without evidence, permissions, verification, and
accountable acceptance. It succeeds when AI's strengths in reasoning,
synthesis, translation, exploration, and candidate generation operate inside
workflows that perform trust-producing work.

The book's central move is not "trust AI" or "do not trust AI." It is:

> Treat AI output as a proposal until a decision acceptance contract records it
> as accepted work for a permitted effect.

The public-facing branding should keep this distinction explicit:

> AI output starts as a proposal. A workflow accepts it for use only after
> required evidence is checked and a named owner accepts the decision or
> authorizes the permitted effect.

## Storytelling Standard

Every major assertion should begin from work the reader can visualize:

1. workplace scene;
2. human fallibility pattern;
3. existing workplace contract;
4. AI analogue;
5. analogy break;
6. decision acceptance contract.

The sidecar claim is:

> High-consequence work learned not to trust consequential human output raw
> either.

Use the human parallel to make controls feel familiar, then name where AI breaks
the analogy: scale, fluency, opacity, retrieval behavior, tool authority, vendor
drift, data leakage, prompt injection, and non-human accountability.
